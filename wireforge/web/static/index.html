How it works

Three steps, all of them checked.

  1. Trace it
  2. Forge it
  3. Prove it

Trace it

It uses the website in a real browser, like a person would — and records every request the site makes to its own backend.

Forge it

It finds the real API behind the page, tests each endpoint, and writes clean, working code for it.

Prove it

A second, independent AI runs the result with its own inputs and compares it against the live page. No match, no ship.

Built around proof, not plausibility.

Evidence before code

Nothing is written until the endpoint has been seen working, twice.

Every action is executed

Code that didn't run and pass its checks never leaves the pipeline.

Verified against the real page

Two runs, real values compared with what the website actually shows.

Builder never grades itself

A separate AI judges the work. It caught our own mistakes too.

Stops at the cart

Checkout, payment and orders are blocked in code. Always.

    Safety

    What it will never do.

    No checkout, no payment, no orders

    Paths containing checkout, payment, /pay, place-order or purchase are refused by the probe tool and by the harness that runs every action. Write actions end at the cart.

    config.BLOCKED_PATH_WORDS · probe.blocked · harness._guard

    No passwords

    Demo sites are public or guest-cart only. Actions may not hard-code cookies or tokens copied from the browser; they fetch what they need at run time.

    forge.SYSTEM

    Starting a run needs the passcode

    Reading the board, actions and results is public. Starting a run drives a real browser and spends credits, so it needs the passcode from the submission, and only one run happens at a time.

    web/server.py · start_run

    Untrusted pages stay data

    Everything a website returns is shown as text on this board, never rendered as HTML, and it never changes what the pipeline is allowed to do.

    static/app.js · esc()
